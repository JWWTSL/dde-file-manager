### 2.2 数据字段说明

- **测试用例基线**：测试用例表中的原始用例总数。
- **转换用例对标测试基线数据**：可自动化用例成果按弱覆盖标准已覆盖的原始用例数；按原始用例 ID 去重，一条 suite case 覆盖多个原始用例时分别累计。
- **AT用例数**：`*.suite.yaml` 中实际生成的 suite case 条目总数，不按原始用例 ID 去重。
- **覆盖率**：`转换用例对标测试基线数据 / 测试用例基线`。
- **可自动化数（测试基线）**：测试用例基线中过滤 AT 无法完成场景后，可自动化的原始用例数。
- **可自动化覆盖率**：`转换用例对标测试基线数据 / 可自动化数（测试基线）`。

### 2.3 弱覆盖 / 强覆盖 / 合并批次口径

- **弱覆盖（主口径）**：suite 跑到原始用例对应的功能入口、操作路径或关键控件，即计为覆盖；不要求完整断言原始最终结果。
- **强覆盖**：suite 必须执行原始关键操作，并断言原始用例预期里的关键最终结果，才计为覆盖。本报告不以此为准。
- **基线变更**：以 `tests/at/统信桌面操作系统V25-用例-文件管理器-1173.xlsx`（1173 条）为唯一基线，不再使用旧的 2400 条用例表；过滤分类沿用既有 raw-filter-audit 按编号映射（1172 条命中，1 条新增按标准 GUI 处理）。
- **存量 AT 套件**：历史套件及后续补全套件共同参与计算；本分支已按假覆盖规则删除 674 条无实质操作 case。

### 2.4 计数与排除规则

- **非 1:1 计数**：一个 suite case 可覆盖多个原始用例，按**原始用例条数**累计；同一原始用例被多个 suite case 覆盖只计一次。
- **不计弱覆盖**：① suite case 无法映射原始用例 ID；② `steps` 为空；③ 原始用例属于过滤集合。
- **一律过滤**：窗口管理、紧凑模式、tooltip/文案/颜色/布局/通知栏等视觉识别、触摸/压力、性能/长时间录制等非标准 GUI 场景。
- 恒等式：`总数 = 过滤数 + 可自动化数`；`可自动化数 = 已覆盖数 + 待补数`。

### 4.1 AT用例数（597）多于转换用例对标测试基线数据（512）的原因

1. **同源拆分/变体**：73 条原始用例被拆成多个 suite case（同一原始 ID 多 case），故 AT用例数大于原始用例数。
2. **映射到被过滤原有用例**：183 个 suite case 的原始 ID 属于过滤集合，不计入覆盖分子。
3. **无基线来源**：0 个 suite case（PR/动态效果等）不含 V25 编号。
4. **入口烟测计入主口径**：入口烟测批次 63 条 case 映射 185 条可自动化原始 ID，按本次宽松标准计入。
5. **一案覆盖多源**：61 个 suite case 同时关联多个原始 ID，按原始条数累计。

可自动化相关的 suite case 为 414 个，去重后弱覆盖 512 条原始用例。
